# dsh-customs-mcp

只读 MCP server：核对报关单证台账自身的内部一致性。

输入是报关员手里已有的台账——每行一张单证或一个商品行——输出是各行彼此之间、或与规则包声明的形式要求之间的差异：
商品编号不是十位、币制不是三位字母、毛重小于净重、单证编号重复使用、申报日期无法解析、占位符没有替换。

它**不判断**申报是否正确、商品归类是否恰当、是否应当缴税。

## 安装

```bash
npx -y dsh-customs-mcp
```

或写进客户端配置：

```json
{
  "mcpServers": {
    "customs": {
      "command": "npx",
      "args": ["-y", "dsh-customs-mcp"]
    }
  }
}
```

没有 npm 依赖，不需要凭据，不联网。Node ≥ 18。

## 工具

| 工具 | 用途 |
|---|---|
| `customs_check` | 用规则包核对 JSON/YAML 台账，返回 Markdown 报告。 |
| `customs_read_docx` | 从 `.docx` 取正文，供你整成台账。 |
| `customs_schema` | 列名契约与全部别名。 |
| `customs_rulebook` | 规则清单、依据性质，以及其中有多少条拿到了逐字条文。 |

## 关于诚实的那部分

规则包为每条规则写明它依据什么，而**7 条里目前有 0 条持有逐字条文**。这一点是规则包自己写的：
这类规则的 `excerpt` 写的是「该条文本次未取得」，而不是转述一份作者没能读到的法规。

`customs_rulebook` 把这个覆盖率作为**算出来的数字**给出，不是作为一句声明：

```json
"coverage": {
  "rules": 7,
  "verbatimClause": 0,
  "uncited": 7,
  "bySeverity": { "warn": 7 },
  "byBasisKind": { "derived-from-principle": 7 }
}
```

所以这些检查是形式与算术上的一致性，严重级封顶 `warn`，而且报告会标明哪几条根本没有执行。
这个主张比一般合规工具弱，但它是这个 server 能支撑得住的唯一一个。

## 例子

```json
{
  "declarationNo": "530120260000123456",
  "rows": [
    { "单证编号": "INV-2026-001", "商品编号": "84713000", "品名": "笔记本电脑",
      "总价": "50000", "币制": "USD", "毛重": "10", "净重": "12", "申报日期": "2026-02-31" }
  ]
}
```

```
- **[提示] CD-002** — 第1行数据
  - 实际：第 1 行「hsCode」的值「84713000」不符合配置的形式
- **[提示] CD-005** — 第1行数据
  - 实际：第 1 行「grossWeight」为 10，「netWeight」为 12，不满足不小于关系
- **[提示] CD-006** — 第1行数据
  - 实际：第 1 行「declaredAt」的值「2026-02-31」无法解析为日期
```

## 范围

- 只吃表：输入是你已经有的台账，JSON 或 YAML。
- `.docx` 由 `customs_read_docx` 支持；`.doc`/`.wps` 是另一种二进制格式，PDF 是**故意拒收**的——PDF 会丢掉单元格结构，重建出来的台账错在哪里，核对本身查不出来。
- 引擎、规则包、表结构都编译进 `src/check.mjs`，所以这个包运行时不安装任何东西。
- 只读：只打开你给的那一个 `.docx` 路径，只读模式，超过 20 MB 直接拒收。不联网、不写文件、不需要凭据。
